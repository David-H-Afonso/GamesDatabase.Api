# Games Database API 3.5.1

## English

- Fix HTTP 500 in account backups when two games have the same title. Games and playlist members now resolve by their owned IDs; no games are merged or deleted.
- Preserve separate metadata and artwork for title/folder-name collisions in stable ID-suffixed folders, such as `Title__gdb_42`. Unique titles keep their existing paths. Folder analysis and explicit image relinking use the same mapping.
- Retain legacy shared folders and existing files. Missing destination artwork can be copied from its verified, account-owned old URL path, including encoded filenames, without HTTP loopback or access to another account's files.
- No schema migration or automatic backup retry. Updating the frontend alone does not install this API fix; deployment remains an owner-controlled action.
- Missing source images remain reported as missing. This patch does not recover deleted files or implement the separately tracked long-running/background backup work.
- Rollback: retain the previous API image and all export folders. Reverting the binary requires no database restore; never restore an older database over newer user edits or delete the new/legacy export folders automatically.

## Español

- Corregido el HTTP 500 al copiar una cuenta con juegos que comparten título. Los juegos y miembros de las listas se resuelven por sus IDs y propietario, sin fusionar ni borrar fichas.
- Las colisiones de nombres usan carpetas distintas con sufijo de ID, por ejemplo `Title__gdb_42`; los títulos únicos conservan sus rutas. El análisis de carpetas y la reparación explícita de URLs usan el mismo criterio.
- Se conservan las carpetas antiguas. Las imágenes pueden copiarse desde su ruta anterior verificada dentro de la misma cuenta, sin llamadas HTTP de vuelta a la API ni lecturas de otras cuentas.
- Sin migración, despliegue ni reintento automático de copias. Actualizar solo el Front no instala este arreglo de API.
- Las imágenes cuyo origen ya no existe siguen notificándose como ausentes. El trabajo de copias largas en segundo plano continúa pendiente.
- Reversión: conservar la imagen anterior de API y todas las carpetas de exportación. No hace falta restaurar la base de datos ni borrar las carpetas nuevas o antiguas para revertir el binario.
