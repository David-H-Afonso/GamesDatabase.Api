# Games Database API 3.0.0

## English

### Owned collection and guided workflows

- Revisioned Home/GOTY, batch/full row results, literal Unicode name search,
  whole-collection statistics and nullable developer extend the owned API.
- Manual playlist/capacity/order contracts support Focus-detail management and
  Shelves. Optional Playing/Upcoming/Favorites rules and previews stay read-only.
- Artwork candidates preserve provider hash URLs and cancellation without game,
  player or persistent Steam app-cache writes. Modern artwork roles stay separate.
- Onboarding supports optional new-user guides and existing-user resume/restart.
  Samples require explicit creation and exact game/list timestamp review;
  concurrent changes, edited data by default and mixed playlists are protected.
- Random choice supports the full owned library or an exact validated displayed-ID
  pool, never silently widened. Configurable recommendations share UTC midnight
  without a recurring discovery worker.
- Positive manual minutes replace Steam or explicitly add to it. Zero/null uses
  Steam; raw sources, additive mode, statistics and SQL filters/sorting stay aligned
  with 64-bit effective minutes. Transfers preserve mode and reject invalid rows.
- View usage persists UTC `lastUsedAt` without changing configuration, manual order
  or edit timestamps. Optional owned creation UUID/hash receipts make manual retry
  idempotent while its game exists; changed payloads on one key return409.
- Steam-first/Wikidata-second metadata previews issue encrypted/signed, owner/
  game/field-bound plans with 10-minute expiry. Apply rejects stale games and writes
  only selected fields, without personal progress, App ID or cache changes.
- Empty databases initialize the current EF model/migration baseline. Existing
  tables/history continue through their actual pending migrations.
- User enumeration is administrator-only. Testing skips env files, uses isolated
  databases and ephemeral DataProtection. Config absence retains typed defaults.
- CSV/JSON/ZIP retain additive owned metadata/preferences and independent artwork;
  missing legacy headers preserve existing values.

### Runtime and schema

.NET 10 LTS/Microsoft-EF 10.0.15, Swashbuckle 10.3.1 and MIT SkiaSharp 4.157.0 replace
the older runtime/image stack. Static WebP quality 90 has pixel budgets and versioned
cache identity; animated GIFs remain original. Container SDK/runtime stages use .NET 10.

`AddCollectionExperience` adds developer and owned preferences.
`AddOnboardingAndSamples` adds guide state, an existing-user default-false guide
flag and sample provenance/artwork fields. Runtime/image/artwork reads add no
other migration. `AddLibraryReviewPreferences` adds view usage, additive-time mode
and export metadata-cache version. `AddRetrySafeGameCreation` adds nullable internal
receipt fields and an owner/key unique index. Their reviewed SQLite native-column
Down paths preserve AUTOINCREMENT high-water marks; Up/Down/Up is tested in an
isolated database, not an authorization to downgrade production. Startup applies
pending migrations.

Before production startup, agree WAL-safe SQLite backup, verify an isolated
restore and retain the prior image digest. Never run Down/restore over newer
user writes automatically. Adopt the API before Front 3.0.0.

The product milestone uses `Release-As: 3.0.0`; gated publication targets only the
tested HEAD and its human notes. Local config/test env files are excluded and the
existing application GPL is included. Publishing is not deployment.

### Validation boundaries

Neither public source provides verified story/completionist durations; Steam
player/average time is not used as such an estimate. Local/Windows tests do not
certify final Linux native-image behavior, hosting, Electron, physical devices,
screen readers or actual production restore.

## Español

La API añade Inicio/GOTY con revisión, búsqueda literal Unicode, estadísticas y
desarrollador. Focus/estanterías reutilizan contratos propios de playlists y
orden/capacidad. Previews y reglas opcionales siguen siendo lecturas.

Los candidatos de imágenes conservan hashes/cancelación sin guardar juegos,
sincronizar jugadores ni escribir caché. La guía es opcional y reanudable.
Sus ejemplos exigen aceptación y revisión exacta de juegos/listas; se protegen
conflictos, editados por defecto y playlists mixtas.

El aleatorio acepta toda la biblioteca o IDs mostrados propios y validados, sin
ampliar el ámbito si falta alguno. Las recomendaciones comparten medianoche
UTC sin worker recurrente. Metadatos Steam/Wikidata emiten planes firmados de
10 minutos; aplicar rechaza timestamps antiguos y conserva datos personales,
App ID y caché. Bases vacías registran el modelo/baseline; existentes migran.
Enumerar usuarios requiere administrador y Testing es aislado/efímero.

Manual positivo sustituye a Steam o se suma explícitamente; cero/null usa Steam.
Se conservan fuentes crudas/modo, aritmética de64 bits en SQL/estadísticas y
transferencias validadas. El uso de vistas guarda `lastUsedAt` UTC sin editar filtros,
orden ni timestamps de edición. Un UUID/hash propio hace idempotentes los reintentos
manuales mientras exista el juego; cambiar el payload con la misma clave devuelve409.

El runtime pasa a .NET 10/Microsoft-EF 10.0.15, Swashbuckle 10.3.1 y SkiaSharp
MIT 4.157.0. WebP con calidad 90 conserva límites e identidad; los GIF animados mantienen original.
Las migraciones de colección/guía añaden metadatos/preferencias/procedencia.
`AddLibraryReviewPreferences` añade uso de vistas, modo aditivo y versión de caché;
`AddRetrySafeGameCreation` añade recibos internos e índice único por propietario.
Sus Down revisados usan DROP COLUMN nativo de SQLite para conservar la secuencia
de IDs. El ensayo aislado de subida/bajada/subida no autoriza un downgrade real.
Antes de producción acuerda copia con WAL, restauración aislada e imagen anterior.
No ejecutes Down ni restaures sobre escrituras posteriores automáticamente.

Actualiza antes del Front 3.0.0. `Release-As: 3.0.0` registra el hito; se publica
solo el HEAD comprobado con sus notas y GPL, sin config/env privados. No se
inventan duraciones desde playtime. Linux final, hosting, Electron, dispositivos,
lector de pantalla y restauración real mantienen verificación separada.
